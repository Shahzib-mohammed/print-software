3. Multi-Tenancy & Isolation
Every tenant-scoped table carries shop_id; PostgreSQL Row-Level Security (RLS) policies restrict each API request's DB session to its authenticated shop_id (shop-admin logins) — platform-admin roles bypass RLS via a separate elevated role.
Object storage keys are namespaced per shop (/{shop_id}/orders/{order_id}/...) so a storage-level leak between tenants is structurally harder.
4. Table Ownership by Module
Matches the Feature-Based backend structure in TRD §8.1, so each dev/module owns a clear slice of the schema:

Module	Tables owned
modules/shops	shops
modules/auth	shop_admins
modules/pricing	price_rules
modules/products	products
modules/orders	orders, order_items, order_files, deletion_logs
modules/payments	payments
modules/printers	printers, print_jobs
modules/subscriptions	subscriptions
5. Indexing Notes
orders(shop_id, status, created_at) — for the live queue and daily/monthly counters.
order_files(expires_at) — for the deletion sweep job.
printers(shop_id, status) — for agent health checks.
payments(gateway_payment_id) unique — for webhook idempotency.
